# ResQFlow v6.1 – change log and verification

## Main changes
- Added `storage_capacity` to inventory and `disaster_type` to campuses, with additive SQLite migration for existing v6 databases.
- Enforced storage limits on stock edits, donations and incoming transfers. Existing approved inbound/outbound transfers are accounted for when validating stock and free capacity.
- Donations now increase the selected/redirected campus inventory immediately and are recorded only when accepted.
- Added an instant consumption simulation endpoint and campus-page action; consumption reduces persisted stock and clamps at zero.
- Approved transfers reserve donor inventory. Dispatch debits the donor once; receipt credits the recipient once. Dispatch and receipt timestamps are persisted.
- Added targeted disaster simulation for flood, earthquake, cyclone and drought. Only the selected campus changes; the original no-body Campus A flood request remains compatible.
- Kept OSRM routing and straight-line offline fallback. Transfer responses expose route geometry, distance, ETA and timestamps.
- Added a manual campus-to-campus transfer form, ETA/status details in the tracker, capacity/disaster indicators on campus cards, and data-derived dashboard metrics.
- Added v6.1 backend regression tests.

## Known limitations
- Disaster multipliers are illustrative demo assumptions (flood 5x, earthquake 2x, cyclone 2.5x, drought 4x water consumption), not predictive hydrology or engineering models.
- Legacy v6 water rows had no recorded storage capacities. The migration assigns a conservative demo capacity buffer relative to current stock; validate these values against real campus tank capacities before any real deployment.
- SQLite is appropriate for this single-instance prototype; concurrent multi-instance deployment should use a server database and stronger transaction/locking strategy.
- Map tiles and live OSRM routes require internet. The offline estimate is explicitly labelled and uses straight-line distance assumptions.
